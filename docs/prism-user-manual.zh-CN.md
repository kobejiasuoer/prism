# Prism 用户操作手册

版本：2026-05-24

## 1. 手册范围

本文面向 Prism 的日常使用者和演示者，说明如何启动系统、理解页面、运行刷新任务、记录交易执行、查看复盘，以及在数据异常时如何处理。

Prism 是投资研究和决策支持系统，不是自动交易系统。所有真实买卖仍由用户在外部券商手动完成，Prism 只负责给出建议、记录执行、暴露风险和辅助复盘。

## 2. 系统组成

Prism 本地运行时主要有三层：

- 前端：`apps/web`，Next.js + React，默认地址 `http://127.0.0.1:8000`。
- 后端：`apps/control-panel`，FastAPI API，默认地址 `http://127.0.0.1:8001`。
- 调度器：`apps/scripts/prism_scheduler.py`，按交易日和固定时间运行刷新任务。

核心页面：

- `/`：指挥中心
- `/portfolio`：持仓管理
- `/discovery`：发现/观察
- `/review`：复盘
- `/settings`：设置
- `/stock/[code]`：股票详情页

## 3. 首次安装

### 3.1 准备 Python 环境

Prism 当前要求 Python 3.14 或更新版本。

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r apps/control-panel/requirements.txt
python -m pip install pytest
```

### 3.2 安装前端依赖

```bash
cd apps/web
npm install
cd ../..
```

如果你使用 `pnpm`，也可以在 `apps/web` 下执行 `pnpm install`。

### 3.3 启动系统

在仓库根目录执行：

```bash
./start_prism.sh
```

默认会启动：

- 前端：`http://127.0.0.1:8000`
- 后端：`http://127.0.0.1:8001`
- 内置调度器：交易日固定时间刷新

只启动前端和后端、不启动调度器：

```bash
PRISM_ENABLE_SCHEDULER=0 ./start_prism.sh
```

自定义端口：

```bash
PRISM_WEB_PORT=8010 PRISM_BACKEND_PORT=8011 ./start_prism.sh
```

### 3.4 验证服务

```bash
curl http://127.0.0.1:8000/healthz
```

如果返回健康状态，说明前端代理和后端服务基本可用。

## 4. 每日使用流程

推荐按这个顺序使用 Prism。

### 4.1 开盘前或首次打开

1. 打开 `http://127.0.0.1:8000/`。
2. 看左侧侧边栏的“今日可信度”和后端连接状态。
3. 如果页面提示数据未到位或可信度不足，进入 `/settings`。
4. 在“今日数据状态 / 交易可用性”确认预期交易日、数据交易日、过期源和阻断项。
5. 在“数据恢复向导”里运行系统推荐的安全刷新。

不要在 readiness 阻断时把页面结论当作可执行交易建议。

### 4.2 看指挥中心

路径：`/`

指挥中心是每天的第一入口，重点看：

- 今日模式：防守、观察、试错或进攻。
- 仓位上限：今天最多允许多少风险敞口。
- 第一动作：今天优先处理什么。
- 禁止事项：今天明确不该做什么。
- 判断链：市场环境、主线强度、持仓压力、新机会质量。
- 行动分组：必须处理、条件触发、只观察、禁止事项。
- 午盘确认：午盘后新增、降级或需要复核的项目。

操作建议：

- 先处理“必须处理”。
- “条件触发”只有达到升级条件才动。
- “只观察”不要提前买入。
- “禁止事项”不要用主观判断绕开。

### 4.3 管理持仓

路径：`/portfolio`

持仓管理页负责把真实账户和 Prism 建议连起来。

首次使用时先确认运行模式：

- 研究态：只研究和复盘，不涉及真钱记录。
- 影子盘：记录意图，但不按真实入金执行。
- 小额实盘：已入金，需要记录成交和对账。

常用操作：

- 刷新持仓行情：更新当前持仓报价和盈亏。
- 现金调整：录入入金、出金或账本修正。
- 补录券商成交：只有外部券商已经真实成交后才填写。
- 记录未成交：挂单未成交、条件未满足或放弃执行时使用。
- 继续观察/放弃：把 Prism 今日动作写回 Decision Ledger。
- 对账：按券商真实现金和总资产修正本地账本差异。

注意事项：

- Prism 不会替你向券商下单。
- “记录已成交”必须填写真实成交数量和价格。
- 小额实盘模式下，如果现金为负或长时间未对账，页面会提示先修正账户状态。

### 4.4 查看发现/观察

路径：`/discovery`

这个页面用于看系统筛出的新机会和观察池。

重点字段：

- 入池原因：为什么进入观察。
- 升级条件：达到什么条件才考虑更进一步。
- 失效条件：出现什么情况就剔除或降级。
- 风险标签：主要风险和限制。
- 主线雷达：当前主题方向和强弱。

常用操作：

- 加入观察计划：把候选加入观察链路，并按需触发刷新。
- 标记已复核：看完某条观察项后，把它从待复核状态闭环。
- 点击股票：进入统一股票详情页。

使用原则：

- 观察池不是买入清单。
- 只有“升级条件”满足，才考虑从观察变成行动。
- 失效条件触发时，优先相信规则边界。

### 4.5 查看股票详情

路径：`/stock/[code]`，例如 `/stock/600690`

进入方式：

- 侧边栏搜索框或 Command-K。
- 从持仓管理页点击股票。
- 从发现/观察页点击候选。
- 直接输入 6 位股票代码 URL。

股票详情页通常会展示：

- 当前结论和主动作。
- Ask 主结论和连续追问。
- 持仓指标、触发条件、发现指标。
- 洞察标签和历史提醒。
- 来源与原始证据。
- Decision Ledger 历史。

使用建议：

- 先看主结论，再看触发条件和失效条件。
- 如果数据新鲜度未通过，页面可能冻结执行内容，只保留证据查看。
- 对单股有疑问时，可以用追问功能补充上下文，但最终仍以可执行动作和风险边界为准。

### 4.6 做复盘

路径：`/review`

复盘页围绕 Decision Ledger 工作，回答三个问题：

- Prism 当时建议了什么？
- 用户实际做了什么？
- 后来结果说明系统偏严、偏松、数据不足，还是执行没跟上？

推荐操作顺序：

1. 看“今日复盘队列”。
2. 选择最高优先级样本，点击开始归因。
3. 在 Review Case 工作台里看当时判断、后续结果和差异。
4. 可点击“AI 预归因”生成草稿。
5. 人工修改主归因、辅助归因、备注和沉淀动作。
6. 点击“保存 Review Case”。

AI 预归因只负责起草，不负责定案。单条样本一般只能形成观察假设，不应该直接变成硬规则调整。

### 4.7 管理设置与任务

路径：`/settings`

设置页是系统运维入口，普通用户最常用的是：

- 今日数据状态 / 交易可用性：看今天能不能使用结论。
- 数据恢复向导：运行推荐的安全刷新。
- 后台刷新守护：查看调度器是否正常。
- 最近运行：查看任务状态、运行详情和日志。
- 自动刷新策略：了解页面是否会自动刷新、推荐运行哪个任务。
- Decision Ledger 健康：查看 capture 和 outcome evaluation 是否正常。

高级功能：

- 参数编辑：修改本地参数 JSON。
- 高级任务：手动运行重算候选池、午盘确认等任务。

谨慎操作：

- 参数强制保存会绕过评估硬拦截，可能影响后续刷新产物。
- 高级任务会重算候选池或特定时段产物，不建议和日常安全刷新混用。

## 5. 刷新任务说明

Prism 的调度器在确认的 A 股交易日运行固定任务。当前常见任务包括：

| 时间 | 任务 | 用途 |
|---|---|---|
| 09:25 | 晨间数据预热 | 准备轻量行情和资金流 |
| 09:32 | 自选股早盘分析 | 刷新持仓/观察链路 |
| 09:40 | 进攻型选股-早盘 | 生成早盘候选 |
| 13:10 | 进攻型选股-午盘 | 午盘刷新候选 |
| 13:45 | 进攻型选股-午盘确认 | 二次确认午盘变化 |
| 14:50 | 收盘前风险刷新 | 收盘前复核风险 |
| 15:05 | 收盘后总控简报 | 生成收盘后简报 |
| 15:35 | Decision Ledger 结果评估 | 评估到期决策结果 |

固定时间任务之外，调度器还会持续守护轻量市场数据新鲜度。在自动刷新窗口内，`quotes.batch` 超过业务新鲜度预算会触发 `quotes_light`，`capital_flow.batch` 超过业务新鲜度预算会触发 `capital_flow_light`；它们仍会遵守交易日、自动窗口、同类运行冲突和冷却时间。也就是说，早上 10:50 打开系统时，行情和资金流不再只能等下一次固定时间刷新。

早盘关键任务到点后如果仍未成功，首页自动刷新检查会在短宽限后补拉起缺失流程；如果调度器正在执行同类任务，页面会识别为运行中，避免重复启动。页面上的手动刷新会遵守任务冷却和冲突检查。遇到“同类刷新任务仍在运行”或“刷新冷却中”，等待任务结束或冷却结束后再试。

## 6. 数据可信度与交易边界

Prism 会把数据状态分成不同层级。使用时记住三条原则：

1. 数据未就绪，先恢复数据，不做交易动作。
2. 观察信号不是买入信号，必须看升级条件。
3. Prism 的建议是决策辅助，不替代用户自己的最终判断。

常见状态理解：

- 数据已就绪：可以按纪律执行，但仍要遵守仓位和风险边界。
- 仅影子盘观察：可以观察和记录，但不建议真钱执行。
- 数据未就绪：先运行安全刷新或修复数据链路。

## 7. 常见问题处理

### 页面提示后端数据不可用

检查后端是否启动：

```bash
curl http://127.0.0.1:8001/healthz
```

如果失败，重新执行：

```bash
./start_prism.sh
```

### 端口被占用

启动脚本会提示占用端口的进程。可以停止占用进程，或换端口启动：

```bash
PRISM_WEB_PORT=8010 PRISM_BACKEND_PORT=8011 ./start_prism.sh
```

### 提示缺少 uvicorn 或 Python 虚拟环境

重新创建并安装后端依赖：

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r apps/control-panel/requirements.txt
```

### 提示缺少 Next.js binary

进入前端目录安装依赖：

```bash
cd apps/web
npm install
```

### 数据过期或 readiness 阻断

进入 `/settings#recovery`，先运行推荐的安全刷新。不要直接运行高级任务替代安全刷新，除非你清楚当前要重算哪条链路。

### 任务一直在运行

进入 `/settings` 的“最近运行”，查看运行详情和日志。若是长任务，等待完成；若失败，先看日志最后一段错误，再决定是否重跑。

### 小额实盘现金为负

进入 `/portfolio`：

1. 检查是否漏记入金。
2. 用“现金调整”补录入金或修正。
3. 用“对账”按券商真实现金和总资产校准。

### 复盘队列没有样本

可能原因：

- 今日还没有 Decision Ledger capture。
- outcome evaluation 尚未运行。
- 近期没有到期或需要归因的样本。

可以在 `/settings` 查看 Decision Ledger 健康，或在 `/review` 手动运行结果评估。

## 8. 推荐使用纪律

每天使用 Prism 时建议遵守：

- 先看 readiness，再看结论。
- 先处理持仓风险，再看新机会。
- 只对满足条件的机会行动。
- 每次真实成交后及时补录。
- 未成交、继续观察、放弃也要记录。
- 每周至少处理一次 Review Case。
- 不在数据阻断时做真钱执行。
- 不把单次复盘结论直接当成长期规则。

开发或维护后建议运行：

```bash

python3 scripts/scrub-secrets.py
```

```bash
npm run typecheck
```
